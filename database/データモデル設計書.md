# LifeGuardian データモデル設計書

## 概要
LifeGuardianシステムのNeo4jグラフデータベース設計を定義します。

## ノード（データの種類）

### 1. Person（本人）
**説明**: システムの中心となる本人の情報
```
プロパティ:
- id: 一意識別子（UUID）
- name: 氏名
- birthDate: 生年月日
- profileImageUrl: プロフィール写真のURL
- currentHealthStatus: 現在の健康状態
- communicationAbility: コミュニケーション能力レベル
- createdAt: 作成日時
- updatedAt: 更新日時
```

### 2. Supporter（支援者）
**説明**: 本人を支援する人々の情報
```
プロパティ:
- id: 一意識別子（UUID）
- name: 氏名
- role: 役割（家族、医師、看護師、ケアマネージャー、法定代理人など）
- email: メールアドレス
- phone: 電話番号
- organization: 所属組織（任意）
- accessLevel: アクセス権限レベル（1-5）
- verificationStatus: 本人確認状態（未確認、確認済み）
- verifiedAt: 本人確認日時
- createdAt: 作成日時
```

### 3. LifeEvent（人生の出来事）
**説明**: 本人の人生における重要な出来事
```
プロパティ:
- id: 一意識別子（UUID）
- title: 出来事のタイトル
- description: 詳細説明
- eventDate: 出来事の日付
- eventType: 種類（誕生、卒業、結婚、仕事、趣味、病気、その他）
- location: 場所
- photos: 写真URL（配列）
- emotionalValue: 感情的価値（1-10）
- createdAt: 作成日時
- createdBy: 作成者ID
```

### 4. Decision（意思決定）
**説明**: 本人が行った重要な意思決定の記録
```
プロパティ:
- id: 一意識別子（UUID）
- category: カテゴリー（医療、財産、生活、その他）
- title: 決定事項のタイトル
- description: 詳細内容
- decisionDate: 決定日
- context: 決定時の状況・背景
- reasoning: 理由・根拠
- witnesses: 立会人ID（配列）
- documentUrl: 関連文書のURL
- isActive: 現在も有効か（真偽値）
- createdAt: 作成日時
- createdBy: 作成者ID
```

### 5. Preference（好み・価値観）
**説明**: 本人の好みや価値観
```
プロパティ:
- id: 一意識別子（UUID）
- category: カテゴリー（食事、趣味、生活様式、医療、その他）
- item: 項目名
- preference: 好みの内容
- importance: 重要度（1-5）
- notes: 備考
- validFrom: 有効開始日
- validUntil: 有効終了日（任意）
- createdAt: 作成日時
- updatedAt: 更新日時
```

### 6. Document（文書）
**説明**: 重要な文書や記録
```
プロパティ:
- id: 一意識別子（UUID）
- title: 文書タイトル
- documentType: 種類（遺言書、委任状、診断書、契約書、その他）
- fileUrl: ファイルのURL
- description: 説明
- uploadedAt: アップロード日時
- uploadedBy: アップロード者ID
- expirationDate: 有効期限（任意）
- tags: タグ（配列）
```

### 7. EmergencyInfo（緊急時情報）
**説明**: 緊急時に必要な情報
```
プロパティ:
- id: 一意識別子（UUID）
- infoType: 情報種別（医療、連絡先、その他）
- title: タイトル
- content: 内容
- priority: 優先度（1-3）
- lastUpdated: 最終更新日時
```

### 8. AIInteraction（AI対話記録）
**説明**: AI意思推定エンジンとの対話記録
```
プロパティ:
- id: 一意識別子（UUID）
- sessionId: セッションID
- query: 質問内容
- response: AI回答
- confidence: 信頼度（0-1）
- usedData: 使用したデータID（配列）
- timestamp: タイムスタンプ
- requestedBy: 要求者ID
```

## リレーションシップ（関係性）

### 1. HAS_SUPPORTER
**説明**: 本人と支援者の関係
```
Person -[HAS_SUPPORTER]-> Supporter
プロパティ:
- startDate: 関係開始日
- endDate: 関係終了日（任意）
- isPrimary: 主要支援者か（真偽値）
```

### 2. EXPERIENCED
**説明**: 本人が経験した出来事
```
Person -[EXPERIENCED]-> LifeEvent
プロパティ:
- significance: 重要度（1-10）
```

### 3. MADE_DECISION
**説明**: 本人が行った意思決定
```
Person -[MADE_DECISION]-> Decision
プロパティ:
- decisionCapacity: 意思決定能力レベル（当時）
```

### 4. HAS_PREFERENCE
**説明**: 本人の好み・価値観
```
Person -[HAS_PREFERENCE]-> Preference
プロパティ:
- confirmedDate: 確認日
- confirmedBy: 確認者ID
```

### 5. OWNS_DOCUMENT
**説明**: 文書の所有関係
```
Person -[OWNS_DOCUMENT]-> Document
プロパティ:
- accessPermission: アクセス許可レベル
```

### 6. HAS_EMERGENCY_INFO
**説明**: 緊急時情報の関連
```
Person -[HAS_EMERGENCY_INFO]-> EmergencyInfo
```

### 7. WITNESSED_BY
**説明**: 意思決定の立会い
```
Decision -[WITNESSED_BY]-> Supporter
プロパティ:
- witnessDate: 立会日
- witnessRole: 立会い時の役割
```

### 8. RELATED_TO
**説明**: 出来事同士の関連
```
LifeEvent -[RELATED_TO]-> LifeEvent
プロパティ:
- relationshipType: 関係の種類（原因、結果、関連など）
```

### 9. BASED_ON
**説明**: AIの推定根拠
```
AIInteraction -[BASED_ON]-> (LifeEvent|Decision|Preference)
プロパティ:
- relevanceScore: 関連度スコア（0-1）
```

## インデックス設計

効率的な検索のために以下のインデックスを作成：

1. Person.id（一意制約）
2. Supporter.id（一意制約）
3. Supporter.email（一意制約）
4. LifeEvent.eventDate
5. Decision.category
6. Document.documentType
7. AIInteraction.timestamp

## セキュリティ考慮事項

1. **アクセス制御**: SupporterのroleとaccessLevelに基づく
2. **監査ログ**: すべての更新操作を記録
3. **暗号化**: 機密情報は保存時に暗号化
4. **バックアップ**: 定期的な自動バックアップ

## 実装時の注意点

1. UUIDは`crypto.randomUUID()`で生成
2. 日時はISO 8601形式で保存
3. 削除は論理削除（deletedAtフィールド追加）を基本とする
4. 大きなファイルは外部ストレージに保存し、URLのみ記録
