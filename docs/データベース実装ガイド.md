# LifeGuardian データベース実装ガイド

## 概要

LifeGuardianでは、以下の2つのデータベースを使用します：

1. **Neo4j** - メインのグラフデータベース（人物関係、意思決定、ライフイベント）
2. **PostgreSQL** - 補助的なリレーショナルDB（認証、ログ、セッション管理）

## Neo4j セットアップ

### 1. Docker環境での起動

```bash
# Docker Composeで起動
make up

# または個別に起動
docker-compose up -d neo4j
```

### 2. Neo4j Browserへのアクセス

- URL: http://localhost:7474
- ユーザー名: neo4j
- パスワード: lifeguardian2024（.envファイルで変更可能）

### 3. スキーマの初期化

```bash
# Makefileを使用
make db-init

# または手動で実行
docker-compose exec neo4j cypher-shell -u neo4j -p lifeguardian2024 < database/schema/setup-all.cypher
```

### 4. サンプルデータの投入

```bash
# Makefileを使用
make db-seed

# または個別のファイルを実行
docker-compose exec neo4j cypher-shell -u neo4j -p lifeguardian2024 < database/schema/03-sample-data.cypher
```

## データモデルの詳細

### ノード（エンティティ）

1. **Person（本人）**
   - システムの中心となる人物
   - 健康状態、コミュニケーション能力を管理

2. **Supporter（支援者）**
   - 家族、医療従事者、ケアマネージャーなど
   - アクセスレベルで権限管理

3. **LifeEvent（人生の出来事）**
   - 重要な出来事を時系列で記録
   - 感情的価値で重要度を表現

4. **Decision（意思決定）**
   - 医療、財産、生活に関する決定
   - 立会人による証明機能

5. **Preference（好み・価値観）**
   - 日常生活の好みを記録
   - AI意思推定の基礎データ

### リレーションシップ（関係）

- `HAS_SUPPORTER`: 本人と支援者の関係
- `EXPERIENCED`: 本人が経験した出来事
- `MADE_DECISION`: 本人が行った意思決定
- `HAS_PREFERENCE`: 本人の好み・価値観
- `WITNESSED_BY`: 意思決定の立会い

## クエリの実行方法

### Cypher Shellの使用

```bash
# Cypher Shellに接続
make cypher-shell

# クエリの実行例
MATCH (p:Person)-[:HAS_SUPPORTER]->(s:Supporter)
RETURN p.name, collect(s.name) as supporters;
```

### プログラムからの接続

```javascript
// Node.js example
const neo4j = require('neo4j-driver');

const driver = neo4j.driver(
  'bolt://localhost:7687',
  neo4j.auth.basic('neo4j', 'lifeguardian2024')
);

const session = driver.session();

try {
  const result = await session.run(
    'MATCH (p:Person {id: $personId}) RETURN p',
    { personId: 'some-uuid' }
  );
  
  const person = result.records[0].get('p');
  console.log(person.properties);
} finally {
  await session.close();
}
```

## バックアップとリストア

### バックアップの作成

```bash
# 自動バックアップ
make db-backup

# 手動バックアップ
docker-compose exec neo4j neo4j-admin database dump \
  --to-path=/backups/backup-$(date +%Y%m%d-%H%M%S).dump neo4j
```

### リストアの実行

```bash
# バックアップからのリストア
docker-compose exec neo4j neo4j-admin database load \
  --from-path=/backups/backup-20240120-120000.dump \
  --database=neo4j --force
```

## パフォーマンスチューニング

### メモリ設定

`.env`ファイルで調整可能：

```bash
NEO4J_dbms_memory_pagecache_size=2G
NEO4J_dbms_memory_heap_max__size=2G
```

### インデックスの確認

```cypher
// 既存のインデックスを表示
SHOW INDEXES;

// インデックスの使用状況を確認
EXPLAIN MATCH (p:Person {id: 'some-id'}) RETURN p;
```

## トラブルシューティング

### 接続できない場合

1. コンテナの状態を確認
   ```bash
   docker-compose ps
   ```

2. ログを確認
   ```bash
   make logs-neo4j
   ```

3. ヘルスチェックの状態を確認
   ```bash
   docker-compose ps | grep neo4j
   ```

### メモリ不足エラー

1. Docker Desktopのメモリ割り当てを増やす
2. `.env`ファイルでNeo4jのメモリ設定を調整
3. 不要なデータをクリーンアップ

## PostgreSQLの管理

### Adminerでの管理

- URL: http://localhost:8080
- システム: PostgreSQL
- サーバー: postgres
- ユーザー名: lifeguardian
- パスワード: lifeguardian2024
- データベース: lifeguardian

### psqlコマンドでの接続

```bash
# PostgreSQLコンテナに接続
docker-compose exec postgres psql -U lifeguardian

# SQLクエリの実行
\dt  # テーブル一覧
SELECT * FROM auth_users;
```

## セキュリティ考慮事項

1. **本番環境では必ずパスワードを変更**
2. **ネットワークアクセスを制限**
3. **定期的なバックアップを設定**
4. **監査ログを有効化**

```cypher
// 監査ログの設定例
CALL dbms.setConfigValue('dbms.logs.query.enabled', 'true');
```
